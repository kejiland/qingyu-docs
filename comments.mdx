## 获取文章评论

```http
GET /api/posts/:id/comments
```

公开接口。**只返回已通过审核的评论**（`status = 'approved'` 或旧数据缺失 `status`），按写入顺序（`rowid ASC`）返回；待审核评论对访客不可见。

**响应：**

```json
{
  "ok": true,
  "postId": "article-slug",
  "comments": [
    {
      "id": "c-9f1c…",
      "post_id": "article-slug",
      "author": "评论者",
      "content": "内容",
      "date": "2025-01-01",
      "status": "approved",
      "parent_id": null
    }
  ]
}
```

**响应头：** `Cache-Control: no-store`——评论是实时互动内容，不做边缘缓存，发表 / 删除后刷新立即可见。

## 发表评论

```http
POST /api/posts/:id/comments
```

公开接口，**无需认证**。

**请求体：**

```json
{
  "author": "评论者名称",
  "content": "评论内容",
  "parent_id": "父评论 ID（可选，回复时传）"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `author` | ✅ | 昵称，最长 30 字符，超长自动截断 |
| `content` | ✅ | 内容，最长 1000 字符，超长自动截断 |
| `parent_id` | ❌ | 父评论 ID；必须属于同一篇文章，否则 `400` |

**成功响应（`201`）：**

```json
{
  "ok": true,
  "comment": {
    "id": "c-9f1c…",
    "author": "评论者名称",
    "content": "评论内容",
    "date": "2025-01-01",
    "status": "approved",
    "parent_id": null
  }
}
```

<Note>
写入顺序上有四道校验：**来源校验 → 频率限制 → 参数与嵌套校验 → 评论数上限 → 重复内容拦截**。频率限制依赖 KV 绑定 `BLOG`，未绑定时会静默失效并在日志里打一条 warning，建议始终绑定。
</Note>

**错误响应：**

| 状态码 | 场景 | error 示例 |
|--------|------|-----------|
| `400` | 缺昵称 / 缺内容 | `请填写昵称`、`评论内容不能为空` |
| `400` | `parent_id` 不存在或不属于该文章 | `回复的评论不存在` |
| `400` | 嵌套超过 3 层 | `最多支持 3 层嵌套回复` |
| `400` | 该文章评论数已达 300 条上限 | `评论数已达上限` |
| `403` | 跨站 Origin（非本站来源的浏览器请求） | `来源校验失败` |
| `409` | 同分区已存在完全相同的昵称 + 内容 | `请勿重复发送相同内容` |
| `429` | 触发每 IP 每分钟 5 条限制 | `评论太频繁，请稍后再试` |
| `500` | D1 未绑定 | `数据库未配置：请创建并绑定名为 DB 的 D1 数据库` |

前端 `saveComment` 会把后端 `error` 文案透传到表单状态行，用户可直接看到失败原因（不再只显示 HTTP 状态码）。

## 删除单条评论（文章维度）

```http
DELETE /api/posts/:id/comments/:cid
Authorization: Bearer <token>
```

需会话 token。评论不存在返回 `404`「评论不存在」，成功返回 `{ "ok": true }`。

## 全局评论列表（管理）

```http
GET /api/comments
Authorization: Bearer <token>
```

**查询参数：** `status`（`approved` / `pending`，留空或 `all` 返回全部）

按 `rowid DESC` 返回，**每条评论附带 `post_title` 字段**（LEFT JOIN `posts`），方便管理后台展示所属文章。

## 审核 / 删除（管理）

```http
PUT  /api/comments/:id      # 审核：{"status": "approved"} 或 {"status": "pending"}
POST /api/comments/:id      # 同上（POST 亦可）
DELETE /api/comments/:id    # 按 id 跨文章删除
```

都需要会话 token。`status` 只接受 `approved` / `pending`，其余值返回 `400`「status 只能是 approved 或 pending」；评论不存在返回 `404`「评论不存在」。

## 嵌套回复

评论通过 `parent_id` 支持**最多 3 层**嵌套（顶层评论 + 两层回复）。超过 3 层的提交会被服务端以 `400`「最多支持 3 层嵌套回复」拒绝；前台的「回复」按钮在第 3 层不再出现。

```
评论 A                        ← 第 1 层
├── 回复 A1 (parent_id: A)    ← 第 2 层
└── 回复 A2 (parent_id: A)
    └── 回复 A2-1 (parent_id: A2)   ← 第 3 层（到此为止）
```

父评论不存在（或已被删除）时，该评论会作为顶层评论展示，不会丢失。

## 重复发送拦截

同一分区（文章 / 留言板，分区即 `post_id`）下，**相同昵称 + 相同内容**只允许出现一次：

- 命中重复返回 **`409`**「请勿重复发送相同内容」，前端透传该提示
- 覆盖「误触双击」与「脚本刷同一段文字」两类场景
- 不同分区互不影响（`gb-note` 与某篇文章各自独立判定），且判定按 `post_id` 隔离

## 安全机制

| 机制 | 说明 |
|------|------|
| XSS 防护 | 输入先清除 ASCII 控制字符（保留 `\n` / `\t`），渲染时统一 HTML 转义 |
| SQL 注入 | 全部查询参数化绑定 |
| 频率限制 | 每 IP 每分钟 5 条，KV 计数（`rate:cmt:<ip>:<分钟窗口>`，TTL 120 秒） |
| Origin 校验 | 携带 `Origin` 的请求必须等于本站 origin 或 `SITE_URL`，否则 `403` |
| 重复发送拦截 | 同分区相同昵称 + 内容只允许一次，返回 `409` |
| 客户端 IP | 仅信任 `CF-Connecting-IP`，不使用可伪造的 `X-Forwarded-For` |
| 主键生成 | `c-` + 16 字节随机 hex，避免同毫秒碰撞 |

## 长度与数量上限

| 限制 | 值 |
|------|-----|
| 昵称 | 30 字符（超出截断） |
| 内容 | 1000 字符（超出截断） |
| 单篇文章评论总数 | 300 条 |
| 单 IP 频率 | 每分钟 5 条 |
| 嵌套层数 | 3 层 |

## 评论审核开关

审核由站点设置键 **`moderate_comments`** 控制（见[站点设置](/settings)），存在 D1 `site_settings` 表：

| 值 | 行为 |
|------|------|
| `"1"` | 新评论写入 `status: 'pending'`，需在后台「评论管理」点「通过审核」后才对访客可见 |
| `"0"` / 缺失 / 其他 | 新评论直接 `status: 'approved'`，发表即公开（默认行为） |

<Warning>
判定是 **严格等值比较**：只有存进去的值恰好是字符串 `"1"` 才开启审核，`"true"` / `"on"` 等都不会生效。
</Warning>
