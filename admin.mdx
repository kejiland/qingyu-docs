管理认证由四个端点组成，全部为 `POST`，数据存在 D1 的 `admin_auth` / `admin_sessions` / `admin_fails` 三张表。

| 端点 | 用途 | 鉴权 |
|------|------|------|
| `POST /api/admin/setup` | 首次设置密码（重置也走这里） | 初始化时可能需 `X-Setup-Key` |
| `POST /api/admin/login` | 登录换会话 token | 密码 |
| `POST /api/admin/logout` | 撤销当前会话 | `Bearer <token>` |
| `POST /api/admin/password` | 修改密码 | `Bearer <token>` + 当前密码 |

## 首次设置密码

```http
POST /api/admin/setup
X-Setup-Key: <BLOG_ADMIN_SETUP_KEY>   # 配置了安装密钥时必须携带
```

**请求体：**

```json
{
  "password": "新管理员密码（至少 8 位）"
}
```

**成功响应（`201`）：**

```json
{
  "ok": true,
  "message": "管理员密码已设置"
}
```

**安装密钥（`BLOG_ADMIN_SETUP_KEY`）为可选项，分两种模式：**

| 模式 | 首次初始化 | 已有密码时（重置场景） |
|------|------|------|
| 已配置（推荐 / 生产） | 必须带匹配的 `X-Setup-Key`，否则 `403`「设置密钥无效」。杜绝「第一个请求到的人即拿管理员」的抢注竞态 | 同样校验 `X-Setup-Key`；匹配后返回 `409`「管理员密码已设置；如需重置，请先删除 D1 表 admin_auth 的 auth 行」 |
| 未配置（兼容旧行为） | 免密钥直接设置密码（全新部署存在先到先得竞态，生产环境建议配置密钥） | 一律返回 `409` 拒绝，防止未授权覆盖 |

| 错误 | 状态码 | error |
|------|--------|-------|
| 密码不足 8 位 | `400` | `密码至少 8 位` |
| 请求体不是合法 JSON（含 BOM / 引号被转义） | `400` | `请求体不是有效 JSON（检查是否含 BOM/引号被转义）` |
| 安装密钥不匹配 | `403` | `设置密钥无效` |
| 已有密码 | `409` | `管理员密码已设置；如需重置，请先删除 D1 表 admin_auth 的 auth 行` |
| 非 POST 方法 | `405` | `Method not allowed` |

<Info>
密码使用 **PBKDF2-SHA256**（16 字节随机盐，100,000 次迭代，Cloudflare WebCrypto 的硬上限）加盐哈希后存 D1，**永不存明文**。初始化成功后 `must_change` 会写成 `0`。
</Info>

## 登录

```http
POST /api/admin/login
X-Setup-Key: <安装密钥>   # 可选：应急通道
```

**请求体：**

```json
{
  "password": "管理员密码"
}
```

**响应：**

```json
{
  "ok": true,
  "token": "64位hex会话Token",
  "expiresIn": 604800,
  "mustChange": false
}
```

`expiresIn` 为秒数（`604800` = 7 天），Token 是 **32 字节随机数**（64 位十六进制），写入 D1 `admin_sessions`（`exp` 存绝对时间戳）。

### 未初始化时的登录行为

| 条件 | 行为 |
|------|------|
| 配置了 `BLOG_ADMIN_SETUP_KEY` | 返回 `403`：`管理员尚未初始化：请先调用 POST /api/admin/setup 并使用安装密钥（环境变量 BLOG_ADMIN_SETUP_KEY）设置密码`（fail-closed，杜绝抢注） |
| 未配置密钥 | **自动初始化**：服务端生成随机默认密码（`xxxx-xxxx`，去掉易混淆字符），写入 D1 并把 `must_change` 置 1，同时签发会话；响应额外带 `defaultPassword` 与 `mustChange: true` |

### 登录限流（三层维度 + 短冷却）

登录失败按三个维度独立计数，**都只做短冷却，不做全局长锁定**：

| 维度 | 阈值 | 冷却 |
|------|------|------|
| 单 IP | 5 次失败 | 15 分钟 |
| 子网（IPv4 `/24`、IPv6 前 4 段） | 15 次失败 | 60 秒 |
| 全局 | 30 次失败 | **仅 10 秒** + `console.warn` 告警 |

- **为什么不做全局长锁定**：全局长锁定等于把可用性交给攻击者——任何人刷够失败次数就能把唯一的管理员锁在门外，属于可用性 DoS。因此全局只冷却 10 秒（对齐 Cloudflare 免费版限流规则的最小窗口）。
- **计数 1 小时老化**；冷却结束后**保留已达阈值的计数**一小段时间，避免「等冷却归零再无限重试」。
- **被限流时直接 429 早退，既不查库也不写库**（顺带挡住「用失败登录刷爆 D1 免费写额度」）。
- 请求仍会跑 PBKDF2 之外的短路判断，但限流期间不会执行密码哈希，避免把「登录 DoS」变成「CPU / 额度 DoS」。
- 登录**成功**时清空本 IP / 本子网 / 全局三层计数，并顺带清理老化计数行与过期会话。
- 提示文案按剩余时间自动切换：不足 1 分钟显示秒，否则显示分钟（如 `尝试次数过多，请 10 秒后再试`）。
- 可选叠加 **Workers 边缘限流绑定**：配置后先过 `env.LOGIN_LIMITER`（每 IP 10 次/分钟/位置），被拦下的请求不查库不写库；**未配置时行为与旧版完全一致**（代码检测不到绑定就回退 D1 计数）。

### 应急通道（break glass）

登录请求携带**正确**的 `X-Setup-Key`（即 `BLOG_ADMIN_SETUP_KEY`）时：

- ✅ **跳过全部三层限流 + 边缘限流**
- ❌ **不跳过密码校验**——密码错了照样 `401`「密码错误」
- 应急通道下的失败**不计数**，避免站长自己把正常路径刷爆

后台登录页在收到 `429` 时会**自动展开**「被限流？用安装密钥登录」入口，填入安装密钥即可立即进入。这保证「攻击者最多让你 10 秒登不进，但永远挡不死你」。

| 错误 | 状态码 | error |
|------|--------|-------|
| 密码错误 | `401` | `密码错误` |
| 未初始化且配置了安装密钥 | `403` | `管理员尚未初始化：请先调用 POST /api/admin/setup …` |
| 命中任一维度的限流 / 冷却 | `429` | `尝试次数过多，请 N 秒后再试` / `…请 N 分钟后再试` |
| 非 POST 方法 | `405` | `Method not allowed` |

## 登出

```http
POST /api/admin/logout
Authorization: Bearer <token>
```

删除该 token 对应的 `admin_sessions` 行（Token 立即作废），返回 `{ "ok": true }`。前端 `cloudLogout` 会先清本地 token 再调用。

## 修改密码

```http
POST /api/admin/password
Authorization: Bearer <token>
```

**请求体：**

```json
{
  "current": "当前密码",
  "password": "新密码（至少 8 位）"
}
```

**响应：**

```json
{
  "ok": true,
  "message": "密码已更新，请重新登录"
}
```

成功后**撤销全部会话**（清空 `admin_sessions`），必须重新登录。

| 错误 | 状态码 | error |
|------|--------|-------|
| 新密码不足 8 位 | `400` | `新密码至少 8 位` |
| 尚未设置管理员密码 | `400` | `尚未设置管理员密码` |
| 当前密码不正确 | `401` | `当前密码不正确` |
| 缺少 / 无效会话 token | `401` | `未授权：请先登录获取会话 token，并在请求头携带 Authorization: Bearer <token>` |

## 认证方式

所有需要认证的接口在请求头中携带 Token：

```http
Authorization: Bearer <token>
```

- Token 存在 D1 `admin_sessions`（`token`、`exp`），有效期 **7 天**
- 前端存于 `localStorage`（键 `qingyu.token`），由 `apiFetch` 自动附带；返回 `401` 时自动登出并跳回登录页
- 会话过期时读路径会顺手删除该行，避免 `admin_sessions` 无限增长
- 兼容旧的静态长令牌：环境变量 `BLOG_WRITE_TOKEN` 仍可作为 `Bearer` 令牌使用（常量时间比较）

<Warning>
`mustChange: true` 会随登录响应返回，**但前端只做提示，不会强制跳转改密**。首次通过随机默认密码初始化的实例，请登录后立刻到「修改密码」改掉它。
</Warning>

<Note>
客户端 IP 只取 Cloudflare 注入的 `CF-Connecting-IP`，不使用可被伪造的 `X-Forwarded-For`——否则攻击者构造该头即可绕过全部按 IP 的限流。

想从源头再加一道门（Cloudflare Access / WAF 限流规则 / Workers 限流绑定三种方案），见 [Cloudflare 配置完全指南 · 第 9 节](https://github.com/kejiland/qingyu-blog/blob/main/CLOUDFLARE_SETUP_GUIDE.md)。
</Note>
