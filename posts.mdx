## 获取文章列表

```http
GET /api/posts
```

公开接口，**不需要认证**。返回全部**已发布**文章的**摘要**：不含正文 `content`、不含密文 `enc`，草稿一律不出现在列表里。

**响应示例：**

```json
{
  "ok": true,
  "posts": [
    {
      "id": "article-slug",
      "title": "文章标题",
      "date": "2025-01-01",
      "excerpt": "摘要...",
      "cover": "https://...",
      "pinned": true,
      "protected": false,
      "tags": ["标签1", "标签2"],
      "category": "",
      "status": "published",
      "search": "正文前 800 个字符，供前端搜索使用"
    }
  ]
}
```

<Note>
**列表没有分页参数**——一次返回全部已发布摘要，由前端自行分页（`config.js` 的 `pageSize`，默认 8，仅影响前台展示）。排序规则：置顶优先，其次按 `date` 倒序。

**`search` 字段**：非加密文章附带正文前 **800 个字符**，供前台搜索直接匹配正文内容；加密文章不带该字段。这也是列表可以省掉 `content` 的原因。
</Note>

**响应头：** `Cache-Control: public, s-maxage=60, stale-while-revalidate=300` + `Cache-Tag: posts`。管理后台用 `api/posts?_=<时间戳>` 穿透边缘缓存取最新列表。

## 获取单篇文章

```http
GET /api/posts/:id
```

公开接口。**草稿只对作者可见**：未携带有效会话 token 时读草稿返回 `404`（`未找到该内容`），避免草稿全文泄漏。

**响应示例：**

```json
{
  "ok": true,
  "post": {
    "id": "article-slug",
    "title": "文章标题",
    "content": "Markdown 正文...",
    "enc": null,
    "tags": ["标签1"],
    "category": "",
    "status": "published",
    "pinned": false,
    "protected": false,
    "date": "2025-01-01",
    "cover": "",
    "excerpt": "摘要..."
  }
}
```

<Info>
加密文章（`protected: true`）的 `content` **恒为空字符串**，正文只以 `enc` 字段返回，形如 `{salt, iv, data}`；前端用用户输入的密码本地解密。列表接口不会返回 `enc`，`enc` 只在详情接口出现。
</Info>

## 创建文章

```http
POST /api/posts
Authorization: Bearer <token>
```

**请求体**（`id` 与 `title` 必填）：

```json
{
  "id": "article-slug",
  "title": "文章标题",
  "content": "Markdown 正文",
  "excerpt": "摘要",
  "cover": "封面图 URL",
  "tags": ["标签1"],
  "category": "",
  "pinned": false,
  "protected": false,
  "password": "加密密码",
  "status": "published"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | **必填**，文章别名，作为主键 |
| `title` | `string` | **必填** |
| `content` | `string` | Markdown 正文；`protected` 为真时会被服务端置空 |
| `tags` | `string[]` \| `string` | 数组，或用中英文逗号分隔的字符串 |
| `pinned` / `protected` | `boolean` | 置顶 / 加密 |
| `enc` | `object` | 加密载荷 `{salt, iv, data}`，由前端生成 |
| `status` | `string` | `published`（默认）/ `draft` / `scheduled` |
| `publish_at` | `number` | 定时发布时间（UTC 毫秒），仅 `scheduled` 使用 |
| `author` | `string` | 文章作者；为空时回退到站点署名 / 个人昵称 |
| `seo` | `object` | 文章级 SEO：`{title, desc, canonical, noindex}`，空白字段自动回退 |
| `og_image` | `string` | 自动分享图 URL |
| `category` | `string` | 分类；编辑器可选择 / 新建议分类，前台首页支持筛选 |

**响应（`201`）：**

```json
{
  "ok": true,
  "post": { "id": "article-slug", "title": "文章标题", "status": "published" }
}
```

- 缺少 `id` 或 `title` → `400`「缺少 id 或 title」
- 已存在同 `id` → `409`「已存在相同 id（article-slug），请用 PUT 更新」
- 写入成功后按 `posts` / `feed` / `sitemap` / `post:<id>` 标签清边缘缓存

## 更新文章

```http
PUT /api/posts/:id
Authorization: Bearer <token>
```

请求体字段与创建一致（服务端按完整对象覆盖写入 `INSERT OR REPLACE`，路径里的 `:id` 优先于请求体 `id`）。`title` 为空返回 `400`「缺少 title」。成功返回 `200`：

```json
{ "ok": true, "post": { "id": "article-slug", "title": "文章标题" } }
```

<Warning>
PUT 是**整篇覆盖**而不是局部合并：未在请求体中出现的字段会按默认值写回。后台编辑器在保存前会先取回完整文章对象，因此正常使用不会丢字段。
</Warning>

## 删除文章

```http
DELETE /api/posts/:id
Authorization: Bearer <token>
```

删除是**原子级联清理**（同一批次执行，同 ID 重建不会复活旧数据）：

| 数据 | 说明 |
|------|------|
| 评论（含回复） | `comments` 表该文章全部记录一并删除 |
| 点赞 / 浏览量 | `stats` 表计数一并删除 |
| 文章本体 | `posts` 表 `id` 行删除 |
| 每日聚合 | `stats_daily` 表该文章的历史趋势**尽力清理**（表缺失或清理失败不阻断删除） |

文章不存在返回 `404`「未找到该内容」，成功返回 `{ "ok": true }`。


## 文章增强接口

| 接口 | 说明 |
|------|------|
| `GET /api/posts/:id/relations` | 双向链接、相关文章推荐 |
| `GET /api/posts/:id/revisions` | 文章版本列表（最多 50 个快照） |
| `GET /api/posts/:id/revisions/:revision` | 单个版本正文与元数据 |
| `POST /api/posts/:id/revisions/:revision/restore` | 恢复指定版本（需会话） |
| `POST /api/admin/preview-link` | 生成草稿预览 HMAC 链接（需会话） |
| `GET /api/preview?token=...` | 预览未发布文章（凭 HMAC token） |

文章级 SEO、作者页与草稿预览的完整行为见 [SEO](/seo)、[多作者](/authors) 与 [预览链接](/preview-links)。
